# Ata 023 — Status dos Requisitos para Projeto Multiplataforma e Microserviços
**Data:** 2025-08-31  
**Participantes:** Marcos A. Menezes, Agente GPT  
**Local:** Remoto / Documentação interna  

## 1. Contexto
Consolidar o estado atual para iniciar o projeto **multiplataforma** (Web/Mobile/Desktop) apoiado em **microserviços**. Já padronizamos a geração de documentação (Pandoc → XeLaTeX) com fontes e `header.tex`. Precisamos agora fechar decisões de arquitetura, requisitos não funcionais, e plano de execução (MVP → Beta → GA), assegurando rastreabilidade por ata.

## 2. Decisões
- **D1 — Documentação:** Padrão oficial com Pandoc/XeLaTeX; `header.tex` versionado (TNR/Helvetica/Monospace).  
- **D2 — Domínios & serviços iniciais:**  
  - `auth` (identidade/autorização), `catalog` (itens/serviços), `docs` (build & artifacts), `gateway-bff` (agregação p/ clientes).  
- **D3 — Comunicação:** REST síncrono para MVP; avaliação de mensageria (NATS/Kafka) após estabilizar contratos.  
- **D4 — Contratos:** OpenAPI 3.1 versionado por serviço; semântica de versão (MAJOR.MINOR.PATCH); depreciações com aviso ≥2 versões.  
- **D5 — Dados:** Banco por serviço (pattern **database per service**); eventos de integração só após modelagem; migrações via tool única (ex.: Atlas/Flyway).  
- **D6 — Segurança:** OIDC/OAuth2 (AuthZ Code + PKCE), secrets via `env` + store (1Password/Keychain local; Vault/KMS na nuvem).  
- **D7 — Contêineres:** Dockerfiles base padronizados, multi-stage, scans (Trivy/Grype) e **SBOM** obrigatório.  
- **D8 — Orquestração:** Dev: Docker Compose; CI: containers; Prod: Kubernetes (Helm + valores por ambiente).  
- **D9 — Observabilidade:** Logs estruturados (JSON), **liveness/readiness** obrigatórios, métricas Prometheus onde couber, tracing OpenTelemetry opcional no MVP.  
- **D10 — CI/CD:** Pipeline mínimo (lint, build, test, scan, image push). Promoção manual para Staging; auto para Dev.  
- **D11 — Multiplataforma:**  
  - Web: React + Vite.  
  - Mobile: React Native (expo) ou Flutter (a decidir na POC).  
  - Desktop: Tauri (preferência) ou Electron (fallback).  
  - BFF agrega e aplica caching/shape de payloads.  
- **D12 — Qualidade:** Testes de contrato (Pact/OpenAPI), integração por serviço, E2E só para fluxos críticos.  
- **D13 — Padrões de repo:** Mono-repo **ou** multi-repo permitido; templates (Taskfile/Makefile) e scaffolds obrigatórios.  
- **D14 — Governança de mudanças:** PRs com checklist (segurança/observabilidade/contrato), CHANGELOG semântico e release tags.
