## 1. Contexto
Consolidação do fluxo de geração de PDF a partir de Markdown usando Pandoc + XeLaTeX.  
Pontos tratados:
- Criação e uso de `header.tex` (fontes via `fontspec`, idioma via `babel`).
- Comando Pandoc com `--pdf-engine=xelatex`, `-V lang=pt-BR` e `--include-in-header=header.tex`.
- Compilação em duas passagens com `xelatex -interaction=nonstopmode -halt-on-error`.
- Correção de colunas `p{<frac>\linewidth}` com `sed` para evitar “Missing number, treated as zero.”.
- Erros identificados e prevenidos:
  - `withBinaryFile: does not exist`: executar Pandoc sem arquivo de entrada.
  - `zsh: parse error near '}'`: colar código LaTeX diretamente no shell.
- Boas práticas: verificar arquivo de entrada (`[ -f "$INPUT" ]`), usar here-doc para gerar `header.tex` e não misturar comentários/código de linguagens diferentes no terminal.

## 2. Decisões
- **D1:** Adotar `header.tex` padrão com `Times New Roman` (rm), `Helvetica` (sf) e `Menlo` (tt).  
- **D2:** Definir `portuguese`/`pt-BR` como idioma no Pandoc/`babel`.  
- **D3:** Compilação sempre em duas passagens do XeLaTeX com `-halt-on-error`.  
- **D4:** Patch obrigatório via `sed` para colunas fracionárias em `longtable/array`.  
- **D5:** Antes do Pandoc, checar existência do arquivo de entrada e falhar com mensagem clara.  
- **D6:** Usar here-doc (`cat > header.tex <<'TEX' ... TEX`) para inserir LaTeX; nunca colar LaTeX “cru” no zsh.  
- **D7:** Manter comandos de abertura no macOS (`open debug_PT.pdf`) somente após sucesso da compilação.
